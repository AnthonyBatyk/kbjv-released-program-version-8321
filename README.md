## 1. Посилання та архітектура

### Тестове середовище

| Компонент | Значення |
|---|---|
| GitHub-репозиторій | `AnthonyBatyk/kbjv-released-program-version-8321` |
| Сайт GitHub Pages | <https://anthonybatyk.github.io/kbjv-released-program-version-8321/> |
| Cloudflare Worker | `kbjv-auth-api-dev` |
| Адреса API | <https://kbjv-auth-api-dev.anthonybatyk.workers.dev> |
| Перевірка API | <https://kbjv-auth-api-dev.anthonybatyk.workers.dev/health> |
| Cloudflare D1 | `kbjv-auth-dev` |
| D1 binding у Worker | `DB` |
| Поточна версія сайту | `v107` |
| Поточна версія Worker | `v91` |

### Як усе пов'язано

```text
Користувач / Safari / Chrome / встановлена PWA
                     │
                     ▼
        GitHub Pages (статичні файли)
        index.html + style.css + script.js
        + utilities.js + sw.js + manifest
                     │
            браузерне сховище
      localStorage / sessionStorage / IndexedDB
                     │
            HTTPS-запити до API
                     ▼
        Cloudflare Worker (v91)
                     │
                  D1 (DB)
       акаунти, сесії, аудит, синхронні знімки
```

- **GitHub Pages** надає інтерфейс: HTML, стилі, JavaScript і ресурси PWA. Сам GitHub не є базою харчових записів користувачів.
- **Браузер** тримає локальні дані поточного акаунта, зокрема продукти, калькулятор, архів, профіль і чернетки.
- **Worker** обробляє реєстрацію, вхід, сесії, доступ адміністратора, аудит та синхронізацію стану користувача.
- **D1** зберігає серверні дані Worker. Локальне сховище та D1 — різні рівні зберігання.
- **Service Worker** кешує файли інтерфейсу для PWA. Він не замінює базу даних і не гарантує роботу авторизації без інтернету.
- **Робочий** та **тестовий** репозиторії / Worker / D1 не слід плутати. Усі інструкції цього README стосуються тестової версії `8321`.

## 3. Загальна навігація

### Основна частина

Чотири вкладки основної панелі:

1. **КБЖВ Блоки** — каталог продуктів.
2. **КБЖВ Калькулятор** — підрахунок з'їдених продуктів та підсумку дня.
3. **КБЖВ Архів** — збережені підсумки, статистика, історія.
4. **Консоль** — журнал дій, стан системи, синхронізація та облікові дії.

Під основною панеллю **праворуч** розташована окрема квадратна стрілка `→`. Вона відкриває другу частину сайту — **«Зручності»**. Стрілка не є п'ятою кнопкою основного рядка.

### Друга частина — «Зручності»

- Верхня панель містить дві вкладки: **«Зручності:»** та **«Консоль:»**.
- Активна вкладка підсвічується; одночасно активна лише одна.
- Нижче панелі **ліворуч** розташована окрема квадратна стрілка `←`, що повертає до попередньої головної вкладки.
- Верхні дані профілю залишаються доступними.
- Друга «Консоль» — **не окрема база й не другий журнал**. Це інша точка доступу до тієї самої консолі.
- Повторне натискання вже активної вкладки не повинно довільно перемикати розділ.

## 4. Авторизація й облікові записи

### Реєстрація

Є поля логіну, пароля та повторення пароля. Для пароля форма показує умови складності:

- щонайменше **11 символів**;
- велика та мала латинські літери;
- цифра;
- спеціальний символ.

Кнопка «Запам'ятати мене» впливає на тривалість сесії. Реєстрація та автентифікація обробляються Worker, а не локальним HTML.

### Вхід

Користувач входить за логіном і паролем. Сесійні дані браузера зберігаються в `localStorage` або `sessionStorage` залежно від «Запам'ятати мене». У Worker v91 звичайна сесія налаштована приблизно на **12 годин**, запам'ятована — приблизно на **30 днів**; остаточний термін дії контролюється сервером.

### Забули пароль

У поточній версії це **запит власнику**, а не автоматичне відновлення через лист на електронну пошту. Форма надсилає запит; власник може переглянути його в адмінці й створити тимчасовий пароль або відхилити запит. Контакти власника можуть відображатися із змінних `OWNER_TELEGRAM` і `OWNER_PHONE`.

### Ролі

- **Учасник (`member`)** — звичайний користувач власних даних.
- **Адміністратор (`admin`)** — має доступ до передбачених адміністративних переглядів.
- **Головний адміністратор (`is_owner`)** — може виконувати особливо чутливі адміністративні дії, визначені Worker.

Права перевіряються на боці Worker; приховування кнопки в HTML саме по собі не є перевіркою доступу.

### Безпека паролів

Worker v91 використовує PBKDF2 із **100 000 ітерацій**. Секретні змінні Worker не повинні зберігатися в GitHub-репозиторії, JavaScript браузера чи README. Тестовий сайт не слід вважати менеджером паролів або повністю незалежним захищеним доменом.

## 5. Профіль

Можливості:

- встановити або змінити фото;
- вказати відображуване ім'я;
- зберегти ПІБ;
- вказати дату народження;
- зберегти поточну вагу в кілограмах;
- зберегти поточний зріст у сантиметрах.

Поля профілю **не впливають автоматично** на основні формули КБЖВ.

### Дата останньої зміни показників

Поруч із вагою та зростом показується дата їхньої **останньої фактичної зміни**. Внутрішні поля профілю:

- `weight_updated_at` — дата зміни ваги;
- `height_updated_at` — дата зміни зросту.

Збереження профілю без зміни конкретного показника не повинно оновлювати його дату. Для старих значень без історії змін показується відсутність відомої дати, а не вигадане число. Дати входять до **повного** експорту та **окремого експорту профілю** і відновлюються під час відповідного імпорту.

## 6. КБЖВ Блоки

Це особистий каталог продуктів із даними про їхній склад та енергетичну цінність.

### Показники продукту

Підтримуються:

- калорійність (ккал);
- білки;
- жири;
- вуглеводи;
- цукри;
- сіль;
- клітковина.

Основні показники в інтерфейсі прив'язуються до бази **100 г** або до підтримуваної одиниці продукту, зокрема **100 мл** для відповідних позицій. Значення можуть мати стан «немає даних»; **невідоме значення не варто підмінювати підтвердженим нулем**.

### Робота з каталогом

- додавання й редагування продукту;
- перегляд картки продукту;
- копіювання КБЖВ;
- передача продукту до калькулятора;
- видалення продуктів із вибором;
- пошук за назвою;
- довільні власні відділи / категорії;
- впорядкування категорій і блоків;
- зміна розташування продуктів;
- сортування за відділами, датою (старіші/новіші), абеткою, випадково, початковим або ручним порядком;
- чотири налаштовувані швидкі ваги продукту.

Використовуйте дані з етикетки або перевіреного джерела. Програма перераховує введені числа, але не може самостійно гарантувати достовірність харчового складу товару.

## 7. КБЖВ Калькулятор

Призначений для збирання даних про з'їдені продукти й підрахунку підсумку.

### Основні можливості

- додати блок продукту зі скопійованого тексту/каталогу;
- ввести текстову чернетку й перетворити її на елемент калькулятора;
- очищувати текст і окремо очищувати блоки;
- створювати розділи;
- налаштовувати швидкі КБЖВ;
- змінювати розташування елементів історії;
- бачити денний підсумок за всіма сімома показниками;
- копіювати денний підсумок;
- зберігати результат в архів.

### Денні цілі

Для калорій, білків, жирів, вуглеводів, цукрів, солі й клітковини можна задати денну ціль, зберегти її та окремо **увімкнути/вимкнути** відображення. Є блок «Залишилось до цілі» і кнопка «Скопіювати залишок». Налаштування цілей можна показувати та приховувати.

Кнопка **«Зберегти цілі»** є дією підтвердження. Не слід припускати, що незбережені зміни в усіх інших формах автоматично стають постійними.

## 8. КБЖВ Архів і статистика

### Збереження денного результату

Калькулятор створює запис архіву з датою, текстом підсумку й доступними числовими показниками. Записи можуть містити склад (композицію), коментар та тип дня. **Кілька записів за одну календарну дату допускаються** і не мають автоматично зникати.

### Коментарі та позначка дня

Для запису можна додати необов'язковий текстовий коментар і **одну** необов'язкову позначку:

- **Відпочинок** (`rest`);
- **Тренування** (`training`);
- **Чітміл** (`cheatmeal`).

Можна не вибирати жодної позначки. Під записом показується коротка назва типу дня без «був/було». Коментарі й позначки входять до експорту/імпорту архіву.

### Пошук історії

Одне поле **«Пошук в архіві...»** шукає за:

- датою: зокрема `YYYY-MM-DD`, `ДД.ММ.РРРР`, `ДД.ММ.РР`;
- вмістом текстового підсумку;
- показниками КБЖВ та іншими текстовими даними запису;
- складом запису;
- коментарями;
- типом дня та поширеними синонімами.

Пошукові варіанти для чітмілу включають `cheat meal`, `cheatmeal`, `чітміл`, `читміл`; підтримуються англійські відповідники тренування й відпочинку. Є також пошук за кількома словами. Додатковий селектор типу дня не потрібен.

### Статистика

- Графік підтримує перемикання між **калоріями, білками, жирами, вуглеводами, цукрами, сіллю та клітковиною**.
- Можна задати проміжок дат «Від» — «До» та опцію поточного дня.
- На графіку враховуються всі релевантні записи, включно з повторними датами.
- Для вибраного періоду показуються кількість записів і унікальних днів.
- Блок **«Середнє значення» за 7, 14 і 30 днів** автоматично використовує **вибрану метрику**, а не завжди калорійність.
- Якщо протягом дня є кілька архівних знімків, для середнього по днях використовується останній знімок відповідного дня, щоб не підсумовувати один день кілька разів.
- Блок «Поточні дані сайту» можна сховати/показати, але обрана метрика й розрахунки від цього не повинні змінюватися.
- Текст середніх значень: `калорій`, `білків`, `жирів`, `вуглеводів`, `цукрів`, `солі`, `клітковини` — **без зайвих дужок**. Внутрішня одиниця обліку залишається ккал або г відповідно.

**Важливо:** графік і усереднені по днях картки можуть використовувати різні способи відображення повторних знімків того самого дня; це не означає, що записи видалені.

## 9. Консоль дій і синхронізація

### Що містить консоль

- журнал дій із датою та часом;
- стан зв'язку з API та номер версії сервера;
- стан локальних і серверних даних;
- кнопку «Оновити стан»;
- кнопку «Синхронізувати зараз»;
- дії розв'язання конфлікту: «Взяти дані із сервера» і «Зберегти дані цього пристрою», коли вони доступні;
- «Повернути дію» (для підтримуваного останнього кроку);
- «Оновити сайт»;
- «Вийти»;
- «Очистити сайт»;
- «Видалити акаунт».

**Одна консоль — два входи:** основна вкладка «Консоль» та вкладка «Консоль» в розділі «Зручності» використовують той самий журнал, статус і дії.

### Версії

- **Версія сайту `v107`** береться з константи `SITE_VERSION` у `script.js`.
- **Версія Worker `91`** повертається окремим запитом `GET /health`; якщо Worker недоступний, статус може бути невідомим.
- `v107` і `v91` **не повинні збігатися**: це різні компоненти, які оновлюються незалежно.

### Журналювання

Фіксуються передбачені події основного сайту та «Зручностей». Для генератора паролів записується **факт генерації/копіювання**, але **не сам пароль**. Для деяких розрахунків журнал може містити скопійований числовий результат.

Локальний журнал і серверний аудит не є тотожними об'єктами з однаковою повнотою, тривалістю зберігання та доступом. Не слід використовувати журнал консолі як єдину резервну копію продуктів чи архіву.

### Конфлікти синхронізації

Якщо локальний і серверний стани розрізняються, не натискайте навмання «Взяти дані із сервера» чи «Зберегти дані цього пристрою». Перед вибором збережіть JSON-експорт і з'ясуйте, яка копія містить актуальніші записи. Перезапис неправильною копією може прибрати важливі зміни з активного стану.

## 11. Зручності — усі функції

Це другий розділ із великим заголовком **«Корисні функції та розрахунки:»**. Кнопка **«Знайти потрібний блок»** відкриває фіксоване вікно зі списком блоків; вибір прокручує до відповідного розділу.

У v107 є **сім блоків** у такому порядку.

### 11.1. Поточний час

- Показує поточний час до **секунди** та дату.
- Дозволяє вибрати часовий пояс зі списку, який підтримує браузер (IANA / `Intl`).
- Автоматично враховує відомі браузеру правила літнього/зимового часу.
- Джерело поточної миті — **годинник пристрою**, а не незалежний атомний сервер часу.
- Вибраний пояс зберігається локально й не повинен скидатися під час переходів між вкладками або звичайного перезавантаження.
- **Кнопки «Очистити» тут немає.** Пояс змінює лише сам користувач, вибираючи інший.

### 11.2. Генератор паролів

- Довжина від **1 до 128** символів.
- Окремо вмикаються малі літери, великі літери, цифри, спеціальні символи.
- Пароль генерується локально через Web Crypto (`crypto.getRandomValues`), а не `Math.random()`.
- Вихідний пароль містить принаймні по одному символу кожного вибраного типу, якщо довжини вистачає.
- Показує приблизну шкалу надійності; ця шкала **не перевіряє** пароль за базами витоків.
- **«Згенерувати пароль»** та **«Очистити»** стоять поруч; **«Копіювати»** — біля поля пароля.
- Сам пароль не входить до експортів, не записується в локальну чернетку й не передається до D1 або консолі.
- Пароль очищується при виході з розділу, перезавантаженні та поверненні зі стану кешованої сторінки, наскільки це контролює код.
- **Зверніть увагу:** скопійований пароль потрапляє до системного буфера обміну пристрою; очистити буфер поза браузером сайт не гарантує.

### 11.3. Коефіцієнт піднятої ваги

Вводяться власна вага та піднята вага (кг). Формула:

```text
Коефіцієнт = піднята вага / власна вага
```

Наприклад, для 170 кг і 68,5 кг коефіцієнт ≈ **2,4817518248×**. Результат можна скопіювати без символу `×`. Підтримуються десяткові числа з комою або крапкою; ділення на нуль недопустиме.

### 11.4. Універсальний конвертер

- **20 категорій, 136 одиниць вимірювання** у поточному каталозі.
- Вгорі — популярні напрямки; першими стоять **фунти → кілограми** та **кілограми → фунти**.
- Для інших напрямків є розділ **«Усі одиниці — вибрати вручну»** з вибором категорії, початкової та кінцевої одиниць і пошуком назв/скорочень.
- Кнопка «Показати інструкцію» розгортає пояснення; «Сховати інструкцію» закриває його.
- Включено масу, довжину, температуру, площу, об'єм, швидкість, час, цифрові дані, тиск, енергію, потужність, частоту та інші категорії.
- Є відмінність між **MB** (десяткові мегабайти) і **MiB** (двійкові мебібайти).
- Для температур враховуються відповідні зміщення шкал; значення нижче абсолютного нуля відхиляються.
- Для одиниць із наближеними фізичними коефіцієнтами точність обмежується самим коефіцієнтом.
- Результат конвертації можна скопіювати.

Приклад: **405 lb = 183,70490985 кг** за точним співвідношенням `1 lb = 0,45359237 кг`.

### 11.5. Перерахунок КБЖВ сирого продукту на готовий

Призначений для круп, рису, гречки та інших продуктів, маса яких змінюється при приготуванні.

**Вхідні дані:**

- маса **сирого** продукту (без тари);
- маса **готового** продукту (без тари);
- КБЖВ сирого продукту на 100 г;
- за бажанням — маса готової порції;
- за бажанням — бажана калорійність порції.

КБЖВ можна ввести вручну або натиснути **«Вибрати з КБЖВ Блоків»**, знайти потрібний продукт і перенести його показники. Продукт із базою **100 мл** не можна безпідставно підставляти як **100 г**. Невідомі значення залишаються невідомими.

**Формули:**

```text
Показник готового на 100 г = показник сирого на 100 г
                             × маса сирого / маса готового

Показник готової порції = показник готового на 100 г
                          × маса порції / 100

Маса порції на бажані K ккал = K × 100 / (ккал готового на 100 г)
```

**Приклад:** 100 г сухої гречки по 340 ккал/100 г після готування важать 250 г. На 100 г готової гречки припадає **136 ккал**. Порція 125 г — **170 ккал**.

**Критично:** ця модель припускає, що загальна кількість поживних речовин партії збереглася. Олія, соуси, зливання рідини, видалення частини продукту або втрата речовин змінюють результат. Це перерахунок за масою, **не лабораторне визначення складу**.

### 11.6. Порівняння цін товарів

- Два варіанти покупки: ціна в гривнях, кількість, одиниця вимірювання.
- Категорії порівняння: **маса, об'єм, штуки, довжина, площа**.
- Можна задати єдину кількість, на яку нормалізується ціна, наприклад 100 г або 1 шт.
- Результат містить порівнянні ціни й вигідніший варіант; доступне копіювання.

```text
Ціна за однакову кількість = ціна упаковки × обрана кількість
                              / кількість товару в упаковці
```

**Приклад:** 700 грн за 1 кг проти 200 грн за 100 г: ціна за 100 г становить відповідно **70 грн** і **200 грн**. Порівнювати потрібно товари в одній валюті й сумісних одиницях.

### 11.7. Калькулятор дат

- Вибір **двох дат** за допомогою календаря.
- Необов'язковий вибір часу з точністю до секунди.
- Показує календарну різницю (роки, місяці, дні, години, хвилини, секунди) та загальні дні/години/хвилини/секунди.
- Якщо час не вказаний, використовується `00:00:00`.
- Результат можна копіювати.
- Обчислення моделює добу як **24 години**; окрема корекція на перехід літнього/зимового часу для конкретної часової зони не виконується.

### 11.8. Спільні правила кнопок у «Зручностях» (v107)

**«Очистити»** є у шести блоках, крім годинника. Кнопка **не блокується** відсутністю даних:

| Ситуація | Повідомлення | Підсвічування |
|---|---|---|
| Немає що очищати | `Немає що очищати` | Червоне |
| Успішно очищено | `Очищено` | Зелене |

**«Копіювати»** / **«Копіювати результат»** є в шести блоках. Кнопка також залишається доступною за порожнього результату:

| Ситуація | Повідомлення | Підсвічування |
|---|---|---|
| Немає результату | `Немає що копіювати` | Червоне |
| Успішно скопійовано | `Скопійовано` | Зелене |
| Помилка доступу до буфера | `Не скопійовано` | Червоне |

Повідомлення/кольори тимчасові: приблизно **1,45 секунди** з анімацією повернення до стандартного синього стану й початкового напису. Очищення одного розділу не повинно змінювати інші. Пароль — окремий випадок: він ніколи не повинен потрапляти в журнал як текст.

Основні дані зберігаються у браузерному сховищі з **префіксом тестового середовища** `kbjv_8321_`, а для увійденого користувача — у просторі імен на кшталт:

kbjv_8321_user_<ID>_products
kbjv_8321_user_<ID>_calculator
kbjv_8321_user_<ID>_archive
kbjv_8321_user_<ID>_profile

Є також службові ключі налаштувань, експорту, синхронізації, активної вкладки, локального журналу тощо. Для черги аудиту може використовуватися IndexedDB (`kbjv-8321-audit-queue`). Підтримується контрольована міграція старих ключів для власника.

### Чернетки «Зручностей»

Крім пароля, заповнені поля «Зручностей» зберігаються **локально для акаунта на поточному пристрої**; ключ має форму:

```text
kbjv_8321_user_<ID>_utilities_draft_v101
```

Збереження спрацьовує після введення та додатково під час згортання/закриття сторінки. Вибраний часовий пояс також входить у локальну чернетку. Чернетка:

- **не** входить до JSON-експорту;
- **не** імпортується з резервної копії;
- **не** синхронізується у Worker/D1;
- **не** є історією всіх колишніх розрахунків;
- **не** включає згенерований пароль.

Отже, після оновлення на **тому самому пристрої та в тому самому сховищі браузера** звичайні поля часто відновляться. На іншому телефоні вони автоматично не з'являться.

### Чому не можна гарантувати «ніколи нічого не пропаде»

Сховище може очистити користувач або сам браузер; приватний режим, нестача місця, зміна домену, зміна акаунта, збій пристрою чи конфлікт синхронізації також можуть спричинити втрату. Поля з **окремою кнопкою «Зберегти»** можуть потребувати явного підтвердження. **Регулярний зовнішній JSON-експорт — обов'язковий засіб захисту цінних даних.**

### Ізоляція основної та тестової версій

Префікси ключів і різні шляхи PWA запобігають **випадковим колізіям** даних, але обидва сайти на `anthonybatyk.github.io` можуть мати спільний браузерний **origin**. Префікс ключа не є криптографічною ізоляцією. Для суворої незалежності сховищ потрібні різні домени/субдомени.

## 13. Експорт та імпорт

### Де знаходяться

У **КБЖВ Блоках** є кнопки **«Експорт бази»** та **«Імпорт бази»**. Перед записом файл/обсяг даних показуються у вікні попереднього перегляду.

### Варіанти експорту

- **«Експортувати усе»** — продукти, архів, калькулятор, текстова чернетка калькулятора, денні цілі, профіль, швидкі КБЖВ, локальна консоль та підтримувані налаштування.
- **«Тільки блоки»** — каталог і пов'язані налаштування категорій/порядку.
- **«Тільки історію»** — архів.
- **«Тільки денну ціль»** — задана денна ціль.
- **«Тільки дані профілю»** — профіль, включно з датами зміни ваги та зросту.

**Не входять:** паролі, парольні секрети, авторизаційний токен, дані сесії та локальна чернетка «Зручностей».

### Формат повної копії

Використовується JSON із маркерами:

```json
{
  "backup_format": "kbjv-full-backup-v2",
  "schema_version": 2,
  "version": 1,
  "exported_at": "<ISO-час-експорту>",
  "export_scope": "all",
  "products": [],
  "archive": [],
  "calculator": [],
  "calculator_draft": "",
  "daily_goal": {},
  "profile": {},
  "calculator_quick_presets": [],
  "console": [],
  "settings": {}
}
```

Це **приклад структури**, а не реальний експорт; конкретна цифра поля `version` є внутрішнім номером експортної бази, який може відрізнятися від `SITE_VERSION` (`v107`). Не редагуйте службові поля вручну без потреби.

### Варіанти імпорту

- **«Імпортувати усе»** — відновити підтримувані дані файлу.
- **«Тільки блоки»** — відновити каталог.
- **«Додати нові блоки»** — додати позиції, яких за правилами порівняння ще немає.
- **«Тільки історію»** — відновити архів.
- **«Додати нову історію»** — додати записи, що не розпізнані як наявні (орієнтир — ID запису, а за його відсутності відповідні сигнатури).
- **«Тільки денну ціль»** — відновити цілі.
- **«Тільки дані профілю»** — відновити профіль.

Не всі варіанти доступні для кожного файлу; вони можуть бути вимкнені залежно від його вмісту. Перед підтвердженням вікно показує кількість даних та очікувані зміни.

### Захист від некоректної копії

Код перевіряє структуру JSON, версію формату, числові поля, деякі дублікати, дані продуктів, архівні записи, профільні параметри та категорії. Є підтримка частини старих структур, зокрема архівних записів із числовими показниками в тексті та кількох записів за одну дату.

Це знижує ризик помилкового імпорту, але **не гарантує** відновлення файлу, який уже був неповним, вручну зіпсований або сформований несумісною майбутньою версією.

### Рекомендований сценарій повної перевірки

1. На початковому пристрої збережіть **повний експорт** у JSON.
2. Запишіть фактичну кількість продуктів, записів архіву, елементів калькулятора; перевірте кілька старих дат.
3. Переконайтеся, що завантажений файл не порожній і має `backup_format` / потрібні масиви.
4. В окремому тестовому акаунті або ізольованому середовищі імпортуйте копію з режимом **«Імпортувати усе»**.
5. Звірте **кількість і вміст** продуктів, архіву, коментарів, типів дня, повторних дат, цілей, профілю та дат зміни ваги/зросту.
6. Перевірте статистику за найстарішим і найновішим днем та експорт після відновлення.
7. Лише після успішної перевірки робіть ризиковані масові зміни.

**Не використовуйте імпорт із перезаписом на єдиній живій копії, якщо не маєте іншого файлу резервної копії.**

## 14. Cloudflare Worker та D1

### Поточний Worker

Окремий Worker `kbjv-auth-api-dev`, версія `91`. У v107 **немає необхідності змінювати його код**: останні версії сайту змінювали HTML/CSS/JS/PWA, а основний API залишився тим самим.

### Технічні деталі Worker

- PBKDF2: **100 000 ітерацій**.
- Стандартна сесія: **12 годин**; запам'ятована: **30 днів**.
- Передбачено обмеження частоти запитів входу.
- Серверний знімок стану обмежений приблизно **6 MiB**; передбачено зберігання частинами розміром до **512 KiB** та обмеження розміру вхідного запиту.
- Схема D1 і необхідні міграції ініціалізуються Worker при відповідних API-запитах, а не самим статичним сайтом.
- `GET /health` **не** запускає створення таблиць D1.

**Увага:** не змінюйте параметри криптографії, авторизації, ролей, формату синхронізації та D1-таблиці заради косметичних правок інтерфейсу. Якщо майбутня функція справді потребує нової серверної схеми, спочатку потрібна окрема перевірка сумісності й резервна копія D1.

## 15. PWA, кеш і офлайн-режим

У поточному `manifest.webmanifest`:

- `name` / `short_name`: `КБЖВ`;
- запуск і scope: `/kbjv-released-program-version-8321/`;
- режим `standalone`;
- темна тема й іконки 192/512.

У `sw.js` для v107:

```js
const CACHE_NAME = "kbjv8321-pwa-v107";
```

Кеш охоплює головну сторінку, CSS, обидва JS-файли, маніфест та іконки. Для файлів CSS/JS використовуються версійні URL на кшталт `?v=107-8321`. Старі кеші **тільки цього тестового префікса** видаляються при активації нової версії. Мережеві API-запити до іншого origin Worker не кешуються цим Service Worker.

### Якщо після оновлення видно стару версію

1. Переконайтеся, що нові файли реально потрапили в правильний тестовий GitHub-репозиторій і опубліковані через GitHub Pages.
2. Перевірте, що **одночасно** узгоджені `SITE_VERSION`, версії URL у `index.html`, `CACHE_NAME` і список ресурсів `APP_SHELL` у `sw.js`.
3. Перезавантажте сторінку з інтернетом, за потреби закрийте та знову відкрийте встановлену PWA.
4. Перед очищенням даних сайту **зробіть JSON-експорт**: видалення браузерного сховища може знищити локальні записи й чернетки.
5. Версію Worker перевіряйте окремо через `/health`, а не за номером інтерфейсу.

В офлайн-режимі можуть відкриватися кешовані сторінки, але **серверний вхід, відновлення пароля, синхронізація та адміністративні дії потребують доступу до API**.

## 16. Вимоги до дизайну та взаємодії

Цей розділ фіксує сталі вимоги проєкту для **всіх майбутніх версій**.

1. **Єдина тема:** «Зручності», Блоки, Калькулятор, Архів, Консоль, Профіль і Адмінка мають узгоджені кольори, розміри кнопок, жирність шрифту, радіуси, відступи та анімації. Нові елементи потрібно будувати з наявних компонентів.
2. **Активна/негативна дія:** успішна операція — коротке **зелене** підтвердження; відсутні дані або помилка — коротке **червоне**; потім повернення до базового стану. Не використовувати нескінченне підсвічування там, де потрібна лише реакція на натискання.
3. **Інтервал реакцій:** орієнтир **1,45 секунди** для стандартних станів кнопок «Зручностей»; при зміні загальних анімацій узгодити всі кнопки.
4. **Порожні дані:** «Очистити» / «Копіювати» повинні повідомляти, що дія неможлива, а не мовчки блокуватися. Винятки мають бути свідомо обґрунтовані.
5. **Фіксовані модальні вікна:** відкрите верхнє вікно — активне; тло та нижчі вікна не прокручуються й не реагують на взаємодію. Закриття верхнього вікна не повинно пересувати фон.
6. **Жодних стрибків масштабу:** фокус на текстовому/числовому полі, клавіатура, вибір дати, меню або модальне вікно не повинні спричиняти автоматичне збільшення/зменшення сторінки. Особливо перевіряти Safari iPhone.

8. **Локалізація:** основні тексти й повідомлення українською; назви одиниць та загальноприйняті символи можуть мати міжнародні скорочення.
9. **Збереження:** перехід між вкладками не повинен непомітно губити підтверджені дані; чернетки «Зручностей» (крім пароля) відновлюються в межах того самого локального сховища.
10. **Безпека:** не писати пароль, токен, секрети та вміст буфера обміну в консоль чи експорт; не відправляти згенерований пароль на сервер.
11. **Стабільність:** косметичні зміни «Зручностей» не повинні змінювати авторизацію, профіль, каталог, архів, обидві консолі та Worker.

**Примітка:** це вимоги й очікувана поведінка, а не сертифікат того, що кожен браузерний баг неможливий. Реальні пристрої потрібно перевіряти.

## 17. Розгортання та оновлення

### Оновлення тестової версії

1. Збережіть **повний JSON-експорт** і копію поточних файлів тестового репозиторію.
2. Підготуйте новий набір HTML/CSS/JS і, якщо потрібно, PWA-файли.
3. Для тестового репозиторію GitHub Pages покладіть файли **в корінь репозиторію**, а не у вкладену папку.
4. Перевірте GitHub Pages: **Deploy from a branch → `main` → `/ (root)`** (або відповідні поточні налаштування конкретного репозиторію).
5. Зробіть Commit і перевірте, чи відкривається сайт за тестовою адресою.
6. Перевірте відображення **правильного номера версії сайту** в консолі та відповідь `/health` із Worker v91.
7. Перевірте мобільний інтерфейс, PWA-кеш, експорти та імпорти.
8. **Не копіюйте** файли до продуктивного репозиторію без окремого рішення про реліз.

Для переходу на v107 потрібні файли з повного пакета `kbjv_pwa_v107.zip`. Якщо в репозиторії вже є правильна v107, **цей README — єдиний новий файл**, який можна додати; решту файлів сайту змінювати не потрібно.

### Чи міняти Worker?

Для цього README та останніх інтерфейсних доопрацювань v107 — **ні**. Worker залишається v91. D1, bindings, секрети й маршрути API не змінюються.

### Перед перетворенням тестової версії на основну

Потрібен окремий план: порівняти GitHub Pages URL, назви Worker і D1, префікси браузерних ключів, scope/ID PWA, серверні секрети, дані користувачів, стан синхронізації, сумісність експорту та поведінку з уже встановленою старою PWA. Просте копіювання `script.js` тестового сайту до продуктивного без адаптації API URL може направити користувачів у **неправильну базу**.

## 19. Типові проблеми й рішення

| Симптом | Що перевірити |
|---|---|
| Консоль показує стару версію сайту | `SITE_VERSION`, HTML і `sw.js`, публікацію GitHub Pages, активний кеш PWA. |
| Сайт v107, сервер v91 | **Це нормально**: інтерфейс і Worker мають незалежну нумерацію. |
| Сайт не авторизується | Доступність Worker `/health`, точну адресу API в `script.js`, CORS, D1 binding, стан акаунта й мережу. |
| Не видно останніх даних на іншому пристрої | Перевірити синхронізацію та чи завершилася передача стану до Worker. Локальна чернетка «Зручностей» між пристроями не переноситься. |
| Зникли записи після імпорту | Зупинити подальші перезаписи, перевірити оригінальний JSON, вибрану область імпорту й серверний конфлікт; відновлювати з окремої резервної копії. |
| Не знаходиться `cheat meal` | Перевірити, чи є саме `day_type=cheatmeal` або відповідний текст у записах; чи активний потрібний акаунт і чи архів завантажено. |
| Немає дати зміни старої ваги | У старому профілі відповідне поле могло бути відсутнім; наступна зміна показника створить нову дату. |
| «Немає що копіювати» | У цьому блоці ще немає валідного результату. Спочатку введіть потрібні дані. |
| «Не скопійовано» | Перевірити дозволи буфера обміну, HTTPS, браузер або режим перегляду. |
| Під час вибору продукту порожній список | Перевірити актуальний каталог поточного акаунта й пошуковий запит. |
| Браузер показує стару PWA | Оновити GitHub Pages, перезапустити PWA; не очищати браузерні дані до резервного копіювання. |
| Модальне вікно зсуває сторінку або з'являється auto-zoom | Перевірити CSS блокування прокрутки, стилі вводу/фокуса та поведінку на **фізичному** iPhone; не вважати настільну емуляцію достатньою. |
| Локальна чернетка не відновилася | Перевірити акаунт, браузерне сховище, приватний режим, квоту та факт очищення даних пристрою. |

## 21. Правила підтримки README

**Цей файл має залишатися повним у кожному наступному релізі.** Під час створення `v108`, `v109` тощо:

1. Брати за основу **повний `README.md` попередньої версії**, а не короткий останній `README_vXX.md`.
2. Змінювати лише розділи, функції яких реально змінилися.
3. Оновлювати фактичні номери версій, назви файлів, кешу та API лише після перевірки коду.
4. Додавати **новий рядок** до «Історії версій», **не видаляючи** попередні.
5. Не стирати розділи профілю, блоків, калькулятора, архіву, консолі, адмінки, зручностей, синхронізації й резервного копіювання тільки тому, що в новому релізі їх не змінювали.
6. За бажанням вести окремий `CHANGELOG.md`, де кожен випуск має короткий список змін; `README.md` залишається **постійним повним довідником**.
7. Не записувати в README секрети, токени, реальні паролі, приватні дані користувачів і неперевірені твердження про безумовну надійність.
8. Документувати відмінності між **фактично перевірено**, **передбачено кодом** і **потребує тесту на живому сервері / iPhone**.

# КБЖВ v97 — тестовий реліз для GitHub Pages

Репозиторій: `kbjv-released-program-version-8321`.
Базова версія — `v96`. Робочий сайт і Cloudflare Worker v91 не змінювалися.

## Зміни

1. **Профіль:** біля поточної ваги та поточного зросту показується дата останньої **фактичної зміни** відповідного числового значення у форматі ДД.ММ.РР. Дані зберігаються в полях `weight_updated_at` і `height_updated_at` профілю, потрапляють у резервну копію та серверний JSON snapshot. Зміна фото, імені чи збереження без зміни ваги/зросту не оновлюють дати. Якщо дата старого вимірювання невідома, відображається «Дата не вказана» без вигадування минулої дати.
2. **Статистика:** графік враховує **всі записи архіву в заданому проміжку**, включно з кількома записами за один день. Показує кількість записів і унікальних днів. Для 1–2 записів графік також доступний; відмову для діапазонів менше трьох днів прибрано. Приймаються коректні старі формати дат при розрахунку. Графік не видаляє і не об'єднує оригінальні записи.
3. **Середні за 7/14/30 днів:** додано «Середнє значення: [обрана метрика]»; замість постійної калорійності показник перемикається разом з графіком між калоріями, білками, жирами, вуглеводами, цукрами, сіллю та клітковиною; одиниці — ккал/г. Якщо на день є кілька архівних знімків, середнє враховує останній знімок дня, щоб не подвоювати підсумок; показує, за скільки календарних днів є записи. Оновлюється навіть за прихованого блоку.
4. **Коментарі архіву:** у наявній формі додано три необов'язкові прапорці «Відпочинок», «Тренування», «Чітміл» з взаємним виключенням. Жодного вибору також можна залишити. Нове поле `day_type` зберігається разом із записом, відображається під коментарем (або без коментаря), бере участь у пошуку по архіву та потрапляє в повний/частковий експорт, імпорт і синхронізацію.
5. **Експорт/імпорт:** резервне копіювання залишає всю кількість і порядок архівних записів. Виправлено втрату числових значень при імпорті старих архівних записів, де показники були тільки у текстовому підсумку (раніше імпорт помилково заповнював відсутні поля нулями). Підтримано архівні записи з однаковими датою й текстом, але різними ID у режимі «Додати нову історію». Підтримано давній формат складу архіву як масив рядків і дати ДД.ММ.РРРР, які нормалізуються для актуальної структури. Повні резервні копії включають нові поля профілю та позначки архіву.
6. Версія сайту та PWA-кешу `v97`. Worker залишається **v91**. Нова схема Worker/D1 не потрібна: v91 перевіряє основну структуру JSON та допускає додаткові текстові поля профілю й архіву.

## Розгортання v96 → v97

У **тестовому** GitHub-репозиторії замінити тільки:
- `index.html`
- `style.css`
- `script.js`
- `sw.js`

`utilities.js`, manifest і зображення іконок не змінилися. Cloudflare Worker, D1, ключі та змінні середовища **не змінювати**.

Перед оновленням рекомендується виконати повний експорт з поточного сайту й зберегти JSON поза браузером. Не замінювати й не очищати реальні дані без резервної копії.

## Перевірки

- `node --check` для `script.js`, `utilities.js` і `sw.js` пройдено.
- Локальний Chromium з ізольованою пам'яттю, без реальних серверних запитів: перевірено профіль, окремі дати зміни, 40 тестових архівних записів за 39 днів (2 записи на один день), перемикання метрик, 7/14/30-денні середні, зміну метрики при прихованих поточних даних, один прапорець на один день, підпис під коментарем, повний експорт та імпорт 40/40 записів, збереження типу дня й дат профілю, відсутність обнулення метрик зі старих записів.
- Перевірено ширини 320, 390, 768, 1280 px без горизонтального переповнення.
- Worker v91 інспектовано як вихідний код без внесення змін; з'єднання з реальним Cloudflare/D1 та фізичним iPhone не тестувалися.

**Обмеження:** без реального JSON користувача неможливо перевірити, які архівні записи вже могли бути відсутні у вихідній основній версії. v97 коректно відображає й переносить наявні записи, але не створює/не відновлює раніше втрачені дані. Для діагностики фактичного архіву потрібен знеособлений експорт JSON.
